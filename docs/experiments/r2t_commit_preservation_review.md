## 중복·중간·실패 기록의 의미

- `*_validation_snapshot/` 및 `f4r_snapshot/`의 사본은 당시 실행 코드를 고정하는 근거다. 현행 코드와 같아도 중복 제거하지 않는다. F1 복원본의 출처와 한계는 해당 README와 manifest를 그대로 따른다.
- `.partial.jsonl`은 중간 실행 기록이며 완결된 결과를 대신하지 않는다. `bnd_hard_attempt1_failed.log` 등 실패 흔적은 진단 문서에 설명된 재실행 원인을 보존한다.
- `.log`, `.log1`–`.log5`, `.rc` 및 번호별 종료코드는 시도별 실행 근거다. 파일 이름만으로 임시 파일이라고 판단해 삭제하지 않는다.
- `preflight.json`과 `preflight_v2.json`, superseded 잠금 및 placeholder 시간표는 수정 전후 이력을 구별하는 근거다. 정본과 동등하게 취급하지 않으며 기존 정정 설명을 유지한다.
- 실제 pilot의 `synthetic_only` 표기 오류와 BEST7/BEST-T 이름·판정 불일치는 결과 문서에 공개된 상태로 보존한다. 이번 커밋은 과학적 결론이나 과거 실행 상태를 수정하지 않는다.
- `.npz` 배열 및 `data/` 아래 실제 입력·사람별 산출은 기존 ignore 정책대로 Git과 이번 동기화에서 제외한다. 저장된 코드·요약·manifest만으로 모든 원자료와 배열이 포함된 완전한 실행 환경을 제공하는 것은 아니다.

## 검토 근거

- 감사와 커밋 준비 사이 325개 파일의 경로·내용 SHA-256·크기·mtime 스냅샷이 동일했다.
- Python 108개 AST, JSON 113개, JSONL 196개 비어 있지 않은 레코드 구문 검사가 통과했다.
- 고정 SHA 목록 81개, F1 snapshot manifest 16개, 실제 pilot results manifest 4개 항목의 로컬 파일 해시가 일치했다. 실제 pilot 산출 검사는 읽기 전용 해시 대조이며 재계산이 아니다.
- 잔여 파일에 원시 영상·바이너리·자격증명 의심 파일명이 없었다. 최대 파일은 309511 bytes였다. 비밀키·토큰·문자열 자격증명 패턴 검사 적중은 0건이었다. 이는 모든 형태의 민감정보 부재를 증명하는 검사는 아니다.
- 실제 pilot의 31개 ID는 로컬에 보관한 공개 AOMIC PIOP1 (`ds002785`) participant 목록에, ds005270 provenance의 6개 ID는 해당 공개 데이터 participant 목록에 모두 존재했다. 코드의 `sub-XXXX`는 형식 설명용 placeholder다. 실명 대응표는 포함하지 않는다.
- 로컬/서버 경로와 공개 데이터 ID는 출처 추적용 기존 기록으로 보존한다. 원본 영상이나 라이선스·인증정보를 포함하지 않는다. 외부 해시 참조 전체를 검증했다고 주장하지 않는다.

## 동기화 원칙

h197 목적지는 `/mnt/data/code/MoBSE`다. 잔여 325개와 앞선 ds005270 세 커밋의 38개 파일을 후보로 비교했을 때 31개는 동일하고 331개는 없었다.
공유 체크포인트 1개는 서버 내용 전체가 로컬 내용의 정확한 접두부여서 로컬 후속 기록을 더해도 서버의 기존 내용은 사라지지 않는다.
검사 시 MoBSE 경로를 사용하는 실행 프로세스는 관찰되지 않았다. 서버의 다른 작업은 변경하지 않는다.

명시적 파일 목록으로 dry-run 후 동기화하며 `--delete`는 사용하지 않는다. `.git`, 원본 영상·`data/`, work/derivatives, 비밀·라이선스·환경은 대상에서 제외한다.
전송 직전 서버 파일 SHA와 모드를 다시 대조하고, 달라진 파일이 있으면 중단한다. 전송 후 SHA-256·모드 및 로컬 HEAD/파일 blob 대응을 별도 manifest로 검증한다.
서버 Git 이력은 갱신하지 않으므로 서버 HEAD가 로컬 HEAD와 같다는 뜻은 아니다. 151명 데이터 준비 폴더는 대상이 아니다.
