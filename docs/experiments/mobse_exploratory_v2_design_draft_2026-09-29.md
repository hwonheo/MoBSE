## 0. 한 문단 요약

v1 은 실행 품질에는 문제가 없었지만 **질문을 검정할 수 없는 자리에 놓였다.** 고른 target 은 단순 FC 분류기가 완벽히 가르고 (S 1.000), 모델은 ROI 가 어디인지 거의 쓰지 못하며, null 은 순열 하나였고, 검정력은 애초에 5–19% 였다. v2 는 **target 을 바꾸는 것보다 "검정할 수 있는 조건" 을 먼저 만드는 데** 무게를 둔다. 네 가지 장치 (포화 선별 gate · 검정력 gate · null 분포 · ROI 정체 구조) 를 main 전에 통과시키고, 그 다음에 target 을 고른다.

## 3. 필수 장치 (초안 명세)

### G-a 포화 선별 gate — main 전, pilot 자료만
- 후보 target 마다 pilot 에서 **S (단순 FC 기준선) 와 NG (그래프 없음)** 를 먼저 돌린다.
- 기준 제안 [결정 필요]: **S 의 pilot balanced accuracy 가 0.95 이상이면 그 target 을 버린다.** 천장 근처에서는 어떤 구조 기여도 잴 자리가 없다.
- 두 번째 기준 제안 [결정 필요]: **NG 가 A 와 같은 수준이면** (차이의 CI 가 0 을 포함) 그 target 은 그래프를 요구하지 않는다는 신호로 본다 — 버리지는 않되 주가설을 "그래프의 가치" 로 두지 않는다.
- v1 에 적용해 보면: S 1.000 → **버렸어야 할 target 이다.** 이 gate 하나가 이번 결과를 미리 막았다.

### G-b 검정력 gate — main 전, 학습 없이 simulation
- v1 의 `precision_scenarios` 장치를 **차단 gate 로 승격**한다.
- 기준 제안 [결정 필요]: 참 효과가 δ 일 때 **P(CI 하한 > 0) ≥ 0.5** 가 아니면 main 을 시작하지 않고 결정 요청을 올린다.
- 못 넘기면 고를 수 있는 것: δ 를 키운다 · N 을 늘린다 (PIOP2 를 학습에 쓰는 설계로 바꾸면 외부 검증은 포기) · endpoint 해상도를 높인다 (아래).
- **endpoint 해상도**: v1 은 사람당 run 이 2 개뿐이라 subject 점수가 {0, 0.5, 1} 세 값이고, A·C 동점이 126 명 중 108 명이었다. run 수를 늘리거나 window 단위 통계로 바꾸면 해상도가 올라간다 [결정 필요 — 통계 단위를 바꾸면 group 가정도 다시 봐야 한다].

### G-c null 분포 — **결정 28: M 을 줄이고 종류를 늘린다**
- 순열 하나로 판정하지 않고 **분포**로 본다. 다만 M 을 키우는 대신 **null 종류**를 늘린다 — "무엇을 보존했느냐" 가 곧 "무엇을 검정하느냐" 이기 때문이다 (Váša & Mišić 2022).
- 세 가지를 각각 M 개씩 (제안 **M = 20** [결정 필요]):
  1. **단순 ROI 순열** — v1 과 같다. 해부학 배치만 깬다 (가장 느슨).
  2. **공간 보존 null (Váša 회전 + 일대일 배정)** — 공간 인접과 반구를 보존한 채 배치만 돌린다 (가장 엄격).
  3. **degree 보존 rewiring** — 연결 수 분포를 보존하고 연결 상대만 바꾼다.
- 읽는 법: A 가 ①만 이기고 ②를 못 이기면 "해부학 배치가 아니라 공간 통계를 쓰고 있다" 는 뜻이다.

**[측정] 2026-09-29 — spin 적용 가능 확인 완료** (h197, `spin_feasibility.py`). `neuromaps`·`netneurotools` 는 venv 에 없지만 **numpy + scipy 만으로 된다.**

| 항목 | 값 |
|---|---|
| Schaefer-100 parcel | 100 (좌 50 · 우 50, 정중선 0) |
| 중심 좌표 | MNI x[−60, 62] · y[−96, 61] · z[−37, 68], 중심에서 중앙 60.5 mm |
| 반구 안 회전 + Hungarian 일대일 배정 20 회 | 거리행렬 상관 중앙 **0.497** (0.322–0.671), **반구 유지 1.000** |
| 대조: 단순 순열 20 회 | 거리행렬 상관 중앙 **0.003** |

→ 회전 null 은 공간 구조를 실제로 보존한다 (0.497 대 0.003). 구현은 parcel 중심 → 반구별 무작위 회전 → `scipy.optimize.linear_sum_assignment` 로 일대일 배정.
**남은 한계**: 이것은 표면 (fsaverage 구면) 기반 spin 이 아니라 **부피 중심 회전** (Váša et al. 2018 계열) 이다. 논문에 쓸 때 그 차이를 적어야 한다.

### G-d ROI 정체 구조
- **결정 28: ROI embedding 과 ROI 별 readout 을 둘 다 돌려 병행 비교한다** (fit 수 2 배). ROI 별 encoder 가중치는 쓰지 않는다.
- 후보:
  - **ROI embedding** — ROI 마다 학습되는 벡터를 encoder 출력에 더한다. 가장 작은 변경.
  - **ROI 별 readout** — 평균 readout 대신 ROI 가중 합 (attention 또는 학습 가중치).
  - **ROI 별 encoder 가중치** — 가장 크고 parameter 가 많이 는다.
- 어느 쪽이든 **`C(x) = A(Pᵀx)` 가 깨지는지 수치로 먼저 확인한다** (midreview 1절과 같은 방법). 깨지지 않으면 그 변경은 H2 를 검정할 수 없다.

**[측정] 2026-09-29 확인 완료** — Mac `.venv`, `mobse.v2.models.MoBSEv2` 에 덧껍데기만 씌워 (저장소 코드는 손대지 않음) 학습 전 무작위 가중치·seed 1729·ROI 100·batch 8 로 쟀다. 스크립트는 scratchpad 의 `equivariance_probe.py`.

| 구조 | max │C(x) − A(Pᵀx)│ | max │C(x) − A(x)│ | 정렬을 쓸 수 있나 |
|---|---:|---:|---|
| **v1 현행** (ROI 평균 readout) | **1.19e−07** | 9.73e−04 | **아니오 — 등변이다** |
| + ROI embedding | **5.68e−03** | 2.36e−03 | 예 |
| + ROI 별 readout | **1.27e−03** | 1.14e−03 | 예 |

- v1 현행의 1.19e−07 은 float 오차 수준이고 midreview 1절이 잰 1.2e−07 과 같다 — 재현됐다.
- **두 후보 모두 등변성을 깬다.** ROI embedding 쪽이 A·C 차이 (2.36e−03) 보다 등변 위반 (5.68e−03) 이 더 커서 정렬 신호가 상대적으로 강하다. ROI 별 readout 은 둘이 비슷한 크기다.
- **주의**: 학습 전 무작위 가중치라 **크기는 성능을 뜻하지 않는다.** 읽을 수 있는 것은 "0 인가 아닌가" 뿐이다.
- 측정 중 걸린 것 (기록): `template_bank` 가 buffer 라 `state_dict` 에 들어간다 — A 의 state_dict 를 C 에 통째로 넣으면 **C 의 null bank 가 A 의 bank 로 덮여** `C(x) = A(x)` 가 되어 버린다. 버퍼를 빼고 싣고, 실은 뒤 bank 가 null bank 인지 assert 로 확인했다.

### G-e 압축 폭
- gate 입력 PCA 차원을 상수 10 에서 **grid 변수**로 올린다 (예 10 · 30 · 100 [결정 필요]).
- 목적은 성능 올리기가 아니라 **D3 이 병목인지 가리는 것**이다: 차원을 늘려 A 가 S 쪽으로 붙으면 병목이 맞고, 안 붙으면 다른 원인이다.

|---|---|---|---|---|

| **T2** | 과제 **조건** 디코딩 (emomatching emotion/control, workingmemory active/passive) | 자료는 있다 (events 전 run) | 낮다 | **창 설계를 다시 해야 한다** |

### T2 의 걸림돌 (확인한 사실)
- emomatching 은 **event-related** 다: trial 48 개 (control 24 · emotion 24), 지속 약 1.8 s, 간격 약 5 s. 60 s 창으로는 조건을 분리할 수 없다.
- workingmemory 는 **6 s 블록** 40 개 (active_change 16 · active_nochange 16 · passive 8). 역시 60 s 창보다 훨씬 짧다.
- 창을 20–30 s 로 줄이면 조건은 분리되지만 **FC 추정이 불안정**해진다 (현 설계는 창당 표본 30). 창 길이·표본 수·필터 통과대역이 한 묶음이라 §3.2 를 다시 설계해야 한다.
- 따라서 T2 는 **가능하지만 전처리 계층부터 새로 설계**하는 일이다.

### T4 가 매력적인 이유
"뇌에서 온 배선도가 가치가 있다" 는 **사전지식의 가치** 주장이다. 사전지식은 보통 **자료가 적을 때** 값어치가 난다. T4 는 target 을 바꾸지 않고 학습 subject 수를 줄여 가며 A−C 를 본다.
- 포화 문제를 우회한다: S 도 저표본에서는 천장에서 내려온다.
- 새 fetch·새 전처리가 필요 없다 (잠긴 분할 안에서 train subset 만 줄인다).
- 실패해도 읽을 거리가 남는다: "정렬된 bank 는 저표본에서도 도움이 안 된다" 는 것 자체가 결과다.
- **위험**: 저표본에서는 분산이 커져 CI 가 넓어진다 → G-b 검정력 gate 를 반드시 먼저 통과시켜야 한다.

## 5. 작업 순서 — **결정 28: 축은 나중에, 포화 선별 gate 가 1 순위**

축 (T1–T4) 을 지금 고르지 않기로 했으므로 순서가 이렇게 된다.

1. **G-a 포화 선별 gate 를 만들어 후보 target 을 실제로 걸러 본다.** 결과를 보고 축을 정한다.
2. 그 사이 **G-d 구조 변경 두 가지를 구현**한다 (target 과 무관한 작업 — 등변성은 이미 확인했다).
3. **G-b 검정력 gate** 를 simulation 으로 만든다 (학습 없음).
4. **G-c 세 가지 null** 을 구현한다 (spin 은 구현 가능 확인 완료).
5. 축이 정해지면 main 설계를 확정하고 계획서를 쓴다.

### 5.2 선별을 **어디서** 할지 — 풀리지 않은 긴장 [결정 필요]

- **pilot 31 명**에서 선별하면 main pool 을 건드리지 않지만 **표본이 작아 추정이 거칠다.** 그래서 기준은 한쪽으로만 써야 한다 — "명백히 포화면 버린다" 는 되고, "포화가 아니니 좋다" 는 안 된다.
- **main pool 126 명**에서 선별하면 정확하지만 **그 target 에 대해 main 을 미리 들여다보는 것**이다 (계획서 §4 의 접근 경계 위반).
- **PIOP2 189 명**은 정확하고 main 을 건드리지 않지만, 결정 27 이 **새 버전의 확증용으로 남겨 둔 자료**다. 선별에 쓰면 그 목적이 훼손된다.
- 초안 권고: **pilot 에서만 선별하고, 기준을 "버리는 쪽으로만" 쓴다.**
