## 0. 사전 규칙

### 0.1 F4 실증 결과와 이 보완판의 관계

- **F4 실증 결과 (그대로)**: 독립 검증 65 판의 요약값 · 판정 (`r2t_t1_f4_review_2026-10-17.md`). 그 판들의 사람별 점수 · 실패 원인 · Δ SD 는 **저장되지 않았고, 이 보완판으로 복구하지 않는다.** 기존 실패 원인을 추정해 채우지 않는다.
- **F4R**: F4 와 **같은 알고리즘** (후보 · 선택 · 예측) 에 (1) 실패 분류 · 처리 규칙을 명확히 하고 (2) 감사용 기록을 남기는 판. 실패가 없는 판에서는 F4 와 선택 · 사람별 점수가 같아야 한다 (시험으로 확인). 수치 오류 처리 규칙이 F4 와 다르므로 수치 오류가 생기는 판에서는 결과가 달라질 수 있다.
- F4R 로 새로 돌린 판의 결과는 F4 검증 결과를 대신하지 않는다.

### 0.2 적합 실패 분류 (restart → 후보 → fold)

| 단위 | 상태 | 뜻 | 분류 |
|---|---|---|---|
| restart | `ok` | 수렴 · 최종 점유율 ≥ 5 % · 공분산 유한 · SPD | — |
| restart | `not_converged` | 500 회 안에 수렴 안 함 | **정상 실패** |
| restart | `sparse_component` | 최종 점유율 < 5 % | **정상 실패** |
| restart | `numerical` | LinAlgError (Cholesky 실패 = 비 SPD 포함) · FloatingPointError · ValueError | **수치 실패** (예외 종류 · 메시지 저장) |
| restart | `nonfinite` | 성공으로 끝났으나 로그우도 · 공분산 · 비율에 비유한 값, 또는 최소 고유값 ≤ 0 | **수치 실패** |
| 후보 (EM a) | ok / failed | restart 하나라도 ok 면 ok (로그우도 최대 restart). 아니면 failed — restart 상태 수를 저장 | |
| fold | ok / fallback / stop | 아래 0.3 | |

### 0.3 처리 규칙 (구현과 문서를 일치시킴)

- **R1**: restart 실패 (정상 · 수치 모두) 는 그 restart 만 빼고, 후보는 남은 ok restart 로 정한다. 모든 restart 기록 (상태 · 이유 · 반복 수 · 로그우도 · 점유율 · seed) 을 남긴다.
- **R2**: inner 에서 failed 후보는 선택에서 빠진다 (빠진 후보 · 이유 저장).
- **R3 (정상 fallback)**: (a) inner 의 모든 후보가 failed 이거나 (b) 선택 후보의 fold train 재적합이 failed 이고, **그 실패한 후보들의 restart 실패가 모두 정상 실패**이면 → 그 fold test 사람의 F4R 예측 = 그 fold BEST 예측 (사전 지정 fallback). 31 명 분모 유지.
- **R4 (수치 중단)**: R3 의 (a) · (b) 상황에서 실패 restart 중 **수치 실패가 하나라도** 있으면 → fallback 하지 않고 fold 를 `stop_numerical` 로 표시, 파이프라인 판정 "중단: 수치 오류로 혼합 실패" (판정 대상에서 제외하고 그대로 보고). 이 경우에도 BEST 와 사람별 기록은 저장한다.
- **R5 (수치 경고)**: 수치 실패 restart 가 있었으나 R3 · R4 상황이 아닌 경우 (다른 restart · 후보로 진행) → 판정 유지, 플래그 "수치 실패 restart k 건 (판정 유지)" 와 위치를 보고.
- **R6**: 최종 선택 적합의 공분산은 유한 · SPD 검사를 다시 한다 (0.2 `nonfinite` 와 같은 검사). 비유한 예측 · NMSE → 중단 (기존과 같음). 비유한 입력 → 중단 (기존과 같음).
- **R7**: 주지표 Δ = NMSE(BEST) − NMSE(F4R), 31 명 전원 (fallback 사람 Δ = 0). 성공 fold 한정 Δ 는 참고. 혼합 실패 fold 수 · fallback 사람 수 · 수치 실패 수 · 중단 fold 수를 따로 보고.
- F4 와의 차이: F4 는 수치 실패도 정상 실패처럼 fallback 했다 (검토 보고서 4 절 e). F4R 은 R4 로 중단한다.

### 0.4 보존 항목 (판마다 `<run>.json` + `<run>.npz`)

- 생성 정보: 세계 종류 · 모수 · world seed · 사람 수 · ROI 수, 설정 전체 (dict), 코드 파일 sha256.
- mask 색인 전체, fold 별 train · test · inner train · inner val 명단.
- BEST: 후보별 inner 점수 · 선택. F4R: 후보 (a, λ, τ, h) 별 inner 점수 · 선택 · 후보 적합 기록 (0.2) · 최종 재적합 기록 · fold 상태 (ok / fallback / stop_numerical) 와 이유.
- 사람별 NMSE (방법마다), 사람별 Δ, Δ 평균 · **SD** · bootstrap CI (주지표 · 참고).
- 예측 (npz): BEST 와 F4R 의 test 예측 배열 (사람 × 창 × mask × frame × 가린 ROI, float64). 정답은 생성기 + seed 로 재생성한다 (저장하지 않음 — 생성 결정론으로 대신, 왕복 시험에서 확인).
- 왕복 일관성 시험: 저장 → 다시 읽기 → (i) 저장 예측 + 재생성 정답으로 사람별 NMSE 를 다시 계산해 저장값과 일치 (ii) 사람별 Δ 로 평균 · SD · CI 를 다시 계산해 일치 (iii) 명단 · mask 로 분리 성질 재확인.
