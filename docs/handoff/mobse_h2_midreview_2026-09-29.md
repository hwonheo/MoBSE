# MoBSE — H2 (A−C) 증명 방식 중간 점검 (2026-09-29)

> 선생님 요청 원문: "ok. 그럼 "A-C"인 H2가 핵심이고 "뇌에서 온 배선도가 가치가 있다"를 증명해야 한다는 것인데. 현재 증명 방식 및 계획에 문제가 없는지 한번 중간 점검을 해 보자"
> 근거: 계획서 v1.1 §1·§5·§6·§8·§9 (Mac 저장소 직접 열람), `mobse/v2/models.py`, 인수인계 문서 G1 [6] 기록, main·aux 결과. 새 학습 없음. 수치 검증 1건 (아래 1).

## 0. 결론
- 실행 품질 (누설 0·잠금·사전등록·해석 규칙) 에는 문제 없음.
- 그러나 "뇌에서 온 배선도가 가치가 있다" 를 H2 로 증명하기에는 설계 약점 5개. 그중 검정력 부족과 pilot A=C 는 main 전에 이미 기록되어 있었다.
- 되돌리기 어려운 지점: PIOP2 는 아직 열지 않은 유일한 자료. 현 설계로 열면 같은 한계로 H2 가 다시 불확실하게 나올 가능성이 크고 [추정], 새 설계의 확증용으로 쓸 수 없게 된다.

## 1. [검증] C 는 "입력 ROI 를 섞은 A" 와 수학적으로 같다
- Mac `.venv`, `mobse.v2.models.MoBSEv2`, 무작위 bank (top 990 양수 edge, self-loop, 대칭 정규화) · seed 1729 순열 · 같은 가중치: `C(x)` vs `A(Pᵀx)` 최대 차 1.2e−7 (float 오차), `C(x)` vs `A(x)` 0.00098 (학습 전 가중치라 크기는 의미 없음).
- 이유: ROI 공유 encoder · `bmm(S,h)` · 공유 Linear · ROI 별 LayerNorm · ROI 평균 readout → 순열 등변 + 평균 불변.
- 의미: H2 는 "배선도가 실제 ROI 위치와 맞을 때 대 어긋날 때" 를 검정한다. 정렬 검정으로는 타당.
- **이전 서술 정정**: 09-29 해석 문서의 "모델이 ROI 식별을 못 해 구조상 A≈C 가 예상된다" 는 과했다. 모델은 이웃 섞기를 통해 정렬을 쓸 수 있다. 다만 ROI 별 가중치가 없고 평균 readout 이라 정렬이 성능에 들어가는 경로가 "연결된 ROI 끼리 신호 평활화" 하나뿐이다.

## 2. 약점
1. **검정 대상의 범위**: A−C 는 "정렬" 만 검정. "뇌 배선도 전체의 가치" 에는 그래프 없음 (NG)·일반 그래프·학습 그래프 대비가 필요. 현재 NG 는 보조이고 A−NG −0.012 [−0.052, +0.028] (그래프 없이도 비슷). 학습·일반 그래프 대조는 없음.
2. **검정력**: G1 [6] 기록 — 참 효과가 δ=0.02 일 때 CI 하한 > 0 확률 0.048–0.191, 80% 검정력 효과 크기 0.041–0.125 (N 126). main 전부터 "불확실" 이 가장 가능성 높은 결과였다. endpoint 해상도도 거침: 사람당 run 2 개 → b_i ∈ {0, 0.5, 1}, A·C 동점 108/126.
3. **target**: 과제 정보가 gate 의 FC 요약 경로로 충분히 들어옴 (NG≈A, S 1.000). 그래프 구조가 필요 없는 문제. 감각·운동·촬영 순서 교란은 계획서 §1 이 이미 인정.
4. **null**: 순열 1 개 (seed 1729) 로 primary 판정. 추가 4 개 (WI-09) 도 분포를 만들기엔 적다. ROI 순열은 공간 인접·반구 대칭까지 깨는 비교적 느슨한 null [추정] — 느슨한 null 도 못 이겼으므로 null 이 엄격해서 생긴 결과는 아니다.
5. **목적과 측정의 거리**: 원래 비전 (AI 계산용 routing template, 효율) 대 H2 (fMRI 템플릿으로 fMRI 과제 분류). 효율 주장은 계획서 §1 에서 제외.
- 절차 신호: pilot e2e A−C 0.00 [−0.12, +0.10], v1 prior sweep 평균 −0.003, G1 [6] 검정력 — 세 경고가 main 전에 있었고 §8 규칙 (δ·N 고정) 에 따라 수용했다. 재발 방지 후보: 사전 검정력이 기준 (예: 50%) 미만인 primary 는 main 전에 결정 요청으로 올리는 gate check.

## 3. 선택지 (계획서 §4-5: main 을 본 뒤 설계 변경 = 새 탐색 버전)
- (가) 현 버전 계획대로: WI-09 null 민감도 + PIOP2 외부. 사전등록 준수 (§8 "내부 결과가 음성이어도 외부 검증 수행"). H2 증명력은 거의 늘지 않음 [추정], PIOP2 소진.
- (나) 현 버전은 내부 결과로 마감 (G3), PIOP2 는 보류하고 새 탐색 버전 설계. 사전등록 이탈이라 사유 기록 필요.
